# 已确认的界面守则

状态：用户已用“ok”确认本阶段十条守则。下列是交互与文案实施依据；当前仅制作审阅稿，不代表应用已改完。视觉配色、字体、图标和最终动效方向仍需后续比较稿确认。

1. **内容先于管理。** 首页先看到节目与继续收听；“导入结果”不占用首页主位置。
2. **一屏一个主要动作。** 空库以导入为主，有内容后优先继续收听；次要动作收进明确入口。
3. **成功不打断。** 打开应用不自动弹出历史报告、删除提示或功能说明；完成在当次操作页表达。
4. **只确认不可撤回的主动删除。** 用户先主动选择具体文件，再确认删除；可撤销操作直接执行并提供撤销。
5. **用内容建立层级。** 封面、分隔与留白组织列表，不给每一行、每段说明套卡片。
6. **默认说明最多一行。** 简介、全文、问题清单与技术细节主动展开；用户导入的正文和文字稿不裁剪、不计入界面精简指标。
7. **控件名独立可懂。** 使用“节目、剧集、待播、文字稿、导入记录”；不让用户先理解内部实现再操作。
8. **全应用使用共同规范。** 主色、字号、间距、图标、浅深色与播放器统一；本轮灰阶线框只定结构。
9. **动作连续、反馈克制。** 方向是细腻跟手，常规 180–280 ms，遵循系统减少动画设置；完成反馈不反复播放、不强迫震动。
10. **保留本机收听习惯。** 不改变导入含义和原播放器能力，不增加账号、上传或新开关。底部“节目 / 待播 / 设置”，RSS 保留为次级入口。

## 用词约定

| 界面优先说 | 避免作为首屏文案 |
| --- | --- |
| 节目、剧集 | Feed、FeedItem、条目 ID |
| 待播 | Queue、队列管理 |
| 文字稿、查找 | transcript、索引 |
| 导入播客、导入记录 | 入库、校验任务、WorkManager |
| 已导入 X 集 | 原始数、保留数、分类数、耗时等并排铺满首屏 |
| RSS 订阅 | 原版首页、上游功能 |
| 原文件已删除 / 已不存在 | 重复出现“删除原压缩包” |

例外：关于与开源许可可出现 AntennaPod、GPL-3.0；RSS 入口保留通用名称；具体错误需要的文件名、集号、格式信息按需展示。

## 可检查的完成线

- 启动路径不得调用自动报告或删除确认；完成任务的通知消费状态应持久化。
- 同一导入记录的 `已删除 / 已不存在` 是终态，重启后不重新出现删除动作。
- 每条剧集的播放键直接播放，标题进入详情，不经过选择弹窗。
- 底栏只有节目、待播、设置；迷你播放器位于其上方。
- 文案统计排除用户内容，前后使用同一脚本和同一口径；原生播放器功能与离线导入接受原有回归验证。

## 弹窗分级

| 场景 | 处理 |
| --- | --- |
| 主动删除仍存在的原 ZIP | 保留一次不可撤回确认，明确导入节目仍保留 |
| 选择剧集操作 | 删除选择弹窗，标题与播放键各司其职 |
| 成功导入 / 历史报告 | 页面内完成，详情由用户主动查看 |
| 部分成功、失败、取消 | 当前导入页显示结果与下一步，不在下次启动重放 |
| 倍速、睡眠定时 | 用户主动打开的操作面板，保留原播放器能力 |
