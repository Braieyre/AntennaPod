# 第一关：界面体检与守则草案

用户反馈：“UI 太丑了”“图标也很丑”“每一次打开都会弹出让我删压缩包，即使我删了”。

## 已核实的基线
定制页面 zip_* 文案42条，原始资源文本超过40字符1条（含格式占位符；剔除占位符后为0条）；zipimport Java中 MaterialAlertDialogBuilder 构造点3处。统计不包含节目正文、文字稿、历史报告或上游所有界面，不能据此宣称全App已量化完成。

真实基线已补齐：本轮首页、节目、剧集选择弹窗、迷你/完整播放器、待播、设置及启动历史结果弹窗；文字稿与应用图标保留真实历史截图。全部图片已复制到本目录，版本、时间、原始来源和未覆盖范围见 [baseline-captures.md](baseline-captures.md)。截图未重构或伪造。

可复现统计见 `scripts/ui_metrics.py` 和 `metrics-baseline.json`；默认 XML 全库、自定资源和两份 Java UI 分开计量，不将导入节目正文算作产品界面文案。

## 病症与处置
- 首页两枚默认大按钮长期占位：空库保留导入主动作；有节目后导入进入顶栏，结果进入设置中的导入记录。
- 长简介抢占剧集区域：默认摘要，用户主动展开全文。
- 原生Spinner、输入框、列表和上游播放器没有统一层级：先制定共同组件与排版规范再替换。
- 点击剧集先弹三选框：标题进入详情，独立播放按钮直接播放。
- 反复导入报告：历史WorkManager完成结果在页面重建后重新投递，lastWorkId只存在内存。改为持久消费状态，启动不自动打开报告。
- 已删仍显示删除：报告sourceUri未更新。删除成功/外部已不存在均记为终态，不再提供删除入口；失败只在当次操作解释并允许主动重试。
- 本地合成日期外露：完整播放器和待播显示 Jan 1, 2000，来自 `ZipSeriesImporter.java:214` 的排序时间。仅隐藏导入节目的这项展示，保留内部排序与真实 RSS 日期。
- 通用 fork 警告误导：`MainPreferencesFragment.java:50–61` 仅按包名 hash 判断，就隐藏 project/关于分类并写入 GPL 指责文字。它不核查源码公开情况，不构成实际许可证违规的证据；应以准确的上游归属、版权、许可证与源码链接替代，并保持关于入口可访问，不删 LICENSE 或版权。
- 常用页面中英混杂：当前设置和播放器来自上游英文标签，自定页使用中文；应统一常用导航与控制的中文层级，更深层 RSS 高级页可按原有语言能力保留。
- 麦克风图标缺乏辨识度：三套视觉稿配套声场、唱片、聆听意象，不再直接更换一个剪贴画。

## 守则（用户已确认）
1. 内容先于管理：首页先看到节目与继续收听。
2. 一屏一个主要动作，其他动作降级。
3. 成功不打断；打开软件不自动弹报告或删除提示。
4. 只对不可撤回的主动删除保留确认。
5. 列表不套无意义卡片；封面、分隔、留白建立层级。
6. 说明最多一行；完整简介、错误和技术细节按需展开。
7. 按钮名称独立可懂，不让用户读教程才能操作。
8. 颜色、字体、间距、图标与播放器统一；浅深色一起设计。
9. 动效细腻跟手，常规180–280ms；跟随系统减少动画设置。
10. 不改变收听习惯与导入语义，不添加登录、上传或额外开关。
