## 本轮根因与证据边界

- 启动历史弹窗：`SeriesLibraryFragment.java` 中 `lastWorkId` 仅为实例内存字段；历史 `WorkInfo` 的完成状态在观察器重连时会再次触发 `showReport()`。
- 原文件状态：`ZipImportWorker.java` 将 `sourceUri` 写入 `last-report.json`，删除回调只显示 Toast，没有把“已删除 / 已不存在”终态持久化。用户反馈中“删了仍弹”与此机制一致。
- 本轮冷启动截图直接复现了自动“导入结果”弹窗；当前记录仅有 OK，未再次复现删除入口，不能将用户历史反馈当成本轮截图中已观察到的按钮。
- 本表不是应用已修改清单。需用户确认本关交互后，才进入实现；视觉三选一仍保留。

## 常用页面新增发现

- `ZipSeriesImporter.java:214` 为稳定顺序写入 `2000-01-01 + index 秒`。真实播放器与待播截图显示 Jan 1, 2000；用户会把它误解为实际发行日期。计划只在导入节目的展示层隐藏这个内部排序字段，真实 RSS 日期仍保留，也不改变排序/数据库语义。
- `app/.../preferences/MainPreferencesFragment.java:50–61` 比较包名 hash 是否等于上游两个常量。自定义包名不匹配就隐藏整个 project 分类，并插入硬编码的 GPL 指责段落。这个条件只识别包名，**没有检查是否公开源码或保留许可证，不能据此断言实际违规**。现有公开源码与准确归属应从可访问的“关于与开源许可”入口呈现。后续正式包名也会触发该分支，所以仅改包名无法解决。
- 上述设置警告来自另一个 Java 文件，不在“42 条 zip_* / 两个自定 UI Java”的量化范围内；本轮以真实常用设置截图和源码定位作为额外发现，不偷换成已全量统计。

## 计量口径补充

初始快速数值为 zip_* 标量 42 条、原始资源文本超过 40 字符 1 条、Java 弹窗构造点 3 处。可复现脚本 `scripts/ui_metrics.py` 另明确剔除格式占位符后的口径：zip_* 标量仍 42 条，汉字 314 个，标准化后超过 40 字符 0 条；包含错误数组及品牌说明的自定资源为 62 项。两个“超长”口径不可混用。用户节目、简介和文字稿正文全部排除；上游全 App 不能用这 42 条推断。
