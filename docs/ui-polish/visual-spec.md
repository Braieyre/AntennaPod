# WP-06 视觉与图标比较稿

交付：[visual-review.html](visual-review.html)。本轮是计划设计稿，不是 Android 实现或 APK；不更改导入、播放器、数据库、签名或包名。用户要求的颜色、原生感觉圆润按钮与圆形播放键贯穿三方向。

## 三个方向

| 方向 | 空间与排版 | 页面布局 | 图标概念 |
| --- | --- | --- | --- |
| A 暖纸与留白（推荐） | 暖象牙、陶土、低饱和青绿；系统 serif 标题与 sans 正文 | 编辑式连续列表、轻量继续收听区、留白分层；播放器保留圆形控制 | 开放、交错的声场曲线 |
| B 清透与精密 | 柔蓝、奶油色；清晰系统 sans、等宽时间 | 节目/剧集采用封面网格，较紧凑的元信息列；播放器尺度更精确 | 唱片圆环、中心与切线 |
| C 夜色与声场 | 石墨、暖白、受控紫粉与青绿；同时有浅色版本 | 首页以大封面收听聚焦，节目页扩大主封面；播放器居中沉浸 | 连续聆听曲线，避免麦克风剪贴画 |

同样的节目、封面、操作和三底栏用于公平比较。页首“并排 / A / B / C”聚焦方向，“各自原貌 / 浅色 / 深色”可切换六套完整色板。选择仅保存在本机 localStorage，不代表已经确认实施，不发送数据。

## 页面与真实基线

每个方向都有节目首页、节目/剧集、完整播放器三页；每一排第一列是已有真实截图 `current-home.png`、`current-programme.png`、`current-player.png`，均为 v1.0.1-preview / API 35。真实截图没有重画。其余九页明确标为计划效果稿。

`sample-assets/episode-01.webp` 至 `episode-03.webp` 为用户提供的“六分钟厨房课”封面原件复制；来源见 `sample-assets/manifest.json`。它们仅用于本地设计稿，不代表产品品牌，也不加入 Android 资源。未创建或嵌入音频。

## 三张规范板

1. **字号与数字**：页标题 28 sp；内容标题 20；小节 18；正文 16；次级 13，常规不低于 12.5；中文默认字距为 0，正文行高约 1.65，时间采用等宽数字。
2. **间距、容器与色彩**：4/8/12/16/20/24/32 dp 尺度；页边距 20–24，触区至少 48；普通按钮圆角 24，大封面 20，面板 24；列表主要用封面、文字与间距，不套机械描边。
3. **字体策略**：推荐系统字体，不新增整套中文字体。A 的标题可使用系统 serif 回退，正文仍系统 sans；B/C 系统 sans。实际 Android 字体替换效果与大字体需实现阶段验证；本稿不宣称已完成真实设备字体或触感验证。

机器可读令牌：[design-tokens.json](design-tokens.json)。HTML 嵌入相同色板，离线无需读取 JSON 网络请求。

## 图标

页面直接展示每种概念的 32 px、64 px、自适应圆形裁切、单色版本。原创 SVG 在 `icons/`，每种含彩色与单色文件。文件和页面均不使用第三方图标图片或字体；普通操作图标为页面内 SVG。图标方向可与另一方向的界面混搭。

## 两段可播放动效

| 场景 | 正常 | 慢放 ×4 | 减少动画 |
| --- | --- | --- | --- |
| 迷你 → 完整 | 同一封面与空间展开 260 ms；内容淡入 200 ms | 展开 1040 ms | 直接到终态，无位移/缩放 |
| 导入完成 | 进度退场 200 ms → 结果落位 220 ms；420 ms 标出一次系统轻触时机 | 总时长 1680 ms | 直接显示完成；网页不震动 |

点击才播放，无自动循环。曲线为 `(0.05, 0.7, 0.1, 1)`。减少动画同时尊重 `prefers-reduced-motion`。重放/复位会取消旧动画；异步完成带代际检查，避免取消后旧回调改写新状态。网页只示意轻触时机，不调用设备震动。

## 检查与限制

- Node JavaScript 语法检查通过。
- 六套色板共 42 个正常文字组合：正文/次级文字在背景、面板、选中底色上，以及主按钮文字；最低 **4.7338:1**，均达到 4.5:1。结果见 [visual-validation.json](visual-validation.json)。图片本身和装饰线不当作正文文字颜色。
- 本地引用的三张真实基线、三张样本 WebP 与规范链接存在；无远程字体、库、分析或请求。
- 已有浏览器策略阻止本地 file URL；本轮未重试受阻路径，也未搭建服务器绕过。因此没有宣称已做浏览器逐像素渲染或真实帧率检查。静态/脚本验证不能替代后续用户的视觉选择与 Android 实现截图对照。
- 不做新的应用构建、签名、发布。下一步停在视觉关卡，用户选择方向、字体策略与图标，可混搭后再实现。
